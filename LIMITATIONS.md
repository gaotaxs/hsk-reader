## 1.18.0 quiz scope and verification notes

- History starts with quizzes completed or explicitly stopped from this version onward; old completed quizzes cannot be reconstructed. Legacy unfinished Reader quizzes retain aggregate scores/positions. Reviewed questions without saved individual outcomes stay locked with “result unavailable”; they are not invented as correct or added to missed-only review.
- Guided tracing is practice, not freehand recognition or a mastery assessment. Completion without stroke mistakes counts as correct; a completed trace with mistakes records a miss. Retry before completion restarts the trace. Unfinished ink paths are not saved; closing/reloading or retrying restarts the current trace. Rotation and pen behaviour still need device verification. Completed answers remain locked. Unavailable writing data offers Retry or Don’t know.
- “Unknown” means New or Learning vocabulary identities, independently for each pronunciation. Its pool includes sentences encountered through the current position or already read in the selected track. It excludes sentence reconstruction so a Known vocabulary identity cannot become its test target. Distractors may still be Known. Character mastery is not inferred from word labels.
- History is retained locally and included in schema-2 backups. It is not silently pruned; large collections consume browser quota. Failed saves preserve exportable in-memory state and report failure, but cannot guarantee persistence after closing. Standalone in-progress navigation snapshots remain session-only.
- Tablet CSS is gated to width 768–1400px and height at least 700px, excluding the phone portrait/landscape viewports used here. Physical iPad touch/Pencil and iPhone Home Screen PWA, WebKit, suspension, offline reopening and OS storage eviction still require device testing. The isolated QA copy disables service workers; its geometry results do not certify offline/update behaviour.

## 1.17.0 verification and migration notes

Physical iPhone installed-PWA/WebKit validation is still pending; Chromium viewport and synthetic service-worker tests do not establish iOS hardware behaviour. Scroll blank areas vertically; pull directly on Chinese words to grade them. Offline readiness validates successful entries for every required asset in the running release cache; later eviction or corrupted contents cannot be ruled out.

Older missed-word records keyed only by 长 did not identify a pronunciation. The original record is preserved under `reading.legacyWordReview`; both pronunciation queues receive a copy unless a specific record already exists. Migration never changes vocabulary status. Old practice questions keep their saved pinyin/options/score/position, and pools recover available contextual pronunciation IDs. An old sentence-order snapshot without vocabulary IDs cannot recover every ambiguous contextual reading; new snapshots save explicit IDs.

# Remaining limitations and next priorities

1. **Physical Apple testing:** iPhone/iPad Safari, Home Screen installation, software-keyboard behaviour, safe-area insets on actual hardware, Apple Pencil stroke grading and palm rejection require real-device testing. Desktop Chromium viewport simulations do not establish these results. Pointer detection only confirms an event reached the page.
2. **PWA end-to-end verification:** the available preview uses an insecure HTTP hostname, which cannot run service workers. Cache installation, offline lookup, update gating and scope isolation were tested in a Node service-worker harness. Actual HTTPS deployment, airplane-mode reopening, browser cache eviction and multi-tab updates remain unverified. Perform the README smoke check after deployment.
3. **Segmentation and polyphony:** longest dictionary-match segmentation is deterministic, not a contextual language model. It recognizes only the supplied vocabulary. 长 selection applies throughout the current passage; per-occurrence readings and automatic contextual disambiguation are future work. Audio uses the example words 长短 and 长大 to encourage the intended reading; speech-engine output is not guaranteed.
4. **Translation and speech:** online translation is third-party, rate-limited, and limited to 500 UTF-8 bytes per request. Long passages use a local word glossary. Speech quality, pronunciation and offline availability depend on the browser/device voices. Live translation quality and actual audio playback were not validated.
5. **Storage:** local browser data can be cleared or evicted. There is no device sync, storage locking, cross-tab conflict resolution or crash-safe multi-key database transaction. Import attempts rollback on storage errors but a browser crash during writing remains a risk. Use downloaded backups and one active study tab.
6. **Study depth:** spaced review is deliberately simple; there is no FSRS model, automatic mastery claim, push notification or background reminder. An unfinished standalone Quiz session is not restored after reload; its completed/stopped history is saved. Reader quiz questions, answers, score and position are restored, as are flashcard deck/position/reveal state. Daily goals count rated flashcards, not elapsed time.
7. **Writing:** tracing is a browser-assisted exercise. Resizing or rotating restarts the active attempt. The bundle covers only the dictionary's 622 unique characters. No pen-only filter or independent palm-rejection guarantee is provided; fingers and styluses use the engine's normal input handling.
8. **Accessibility/performance:** semantic labels, focus outlines, keyboard controls, textual quiz feedback and reduced-motion support are implemented. This is not a certified WCAG audit. VoiceOver, switch control, real touch ergonomics and very large passage performance on older devices still need testing. Very long inputs are capped at 200,000 characters for new edits.

Highest-value follow-up: real iPhone/iPad deployment smoke tests, then per-token polyphonic selection, contextual example sentences, and robust multi-tab storage coordination. These should precede claims of a fully validated public launch.
