# Remaining limitations and next priorities

1. **Physical Apple testing:** iPhone/iPad Safari, Home Screen installation, software-keyboard behaviour, safe-area insets on actual hardware, Apple Pencil stroke grading and palm rejection require real-device testing. Desktop Chromium viewport simulations do not establish these results. Pointer detection only confirms an event reached the page.
2. **PWA end-to-end verification:** the available preview uses an insecure HTTP hostname, which cannot run service workers. Cache installation, offline lookup, update gating and scope isolation were tested in a Node service-worker harness. Actual HTTPS deployment, airplane-mode reopening, browser cache eviction and multi-tab updates remain unverified. Perform the README smoke check after deployment.
3. **Segmentation and polyphony:** longest dictionary-match segmentation is deterministic, not a contextual language model. It recognizes only the supplied vocabulary. 长 selection applies throughout the current passage; per-occurrence readings and automatic contextual disambiguation are future work. Audio uses the example words 长短 and 长大 to encourage the intended reading; speech-engine output is not guaranteed.
4. **Translation and speech:** online translation is third-party, rate-limited, and limited to 500 UTF-8 bytes per request. Long passages use a local word glossary. Speech quality, pronunciation and offline availability depend on the browser/device voices. Live translation quality and actual audio playback were not validated.
5. **Storage:** local browser data can be cleared or evicted. There is no device sync, storage locking, cross-tab conflict resolution or crash-safe multi-key database transaction. Import attempts rollback on storage errors but a browser crash during writing remains a risk. Use downloaded backups and one active study tab.
6. **Study depth:** spaced review is deliberately simple; there is no FSRS model, automatic mastery claim, push notification or background reminder. A running quiz is not restored after reload; flashcard deck/position/reveal state is. Daily goals count rated flashcards, not elapsed time.
7. **Writing:** tracing is a browser-assisted exercise. Resizing or rotating restarts the active attempt. The bundle covers only the dictionary's 622 unique characters. No pen-only filter or independent palm-rejection guarantee is provided; fingers and styluses use the engine's normal input handling.
8. **Accessibility/performance:** semantic labels, focus outlines, keyboard controls, textual quiz feedback and reduced-motion support are implemented. This is not a certified WCAG audit. VoiceOver, switch control, real touch ergonomics and very large passage performance on older devices still need testing. Very long inputs are capped at 200,000 characters for new edits.

Highest-value follow-up: real iPhone/iPad deployment smoke tests, then per-token polyphonic selection, contextual example sentences, and robust multi-tab storage coordination. These should precede claims of a fully validated public launch.
